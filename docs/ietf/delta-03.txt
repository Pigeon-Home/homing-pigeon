U+2000-U+200A, and the rest of the gap set). The prose says
the prose wins and invites the reader to finish the ABNF.
The code in runner/wire/subject.py already matches the
complement of the gap set, and it treats a unit separator
as part of a word. The ABNF cannot consume U+001F at all.

reader to close it.

-word-char      = %x21-10FFFF ; any code point that is not a gap-char

================ the disclosure object ================

The -02 sentence "in exactly this form" is false. The
reference sends `type`, `transport`, `v`, and a trailing
newline as well as `disclosure` and `platform`. This delta
does not remove those members from the code. It stops the
draft from claiming the example is what the program sends,
and it tells a receiver to ignore members it does not know,
so today's sender stays readable.

-The reference implementation includes the platform disclosure in the handshake in exactly this form: it answers the offer on every handshake, at the tier its local configuration sets.
+A receiver MUST ignore object members it does not recognize. The reference implementation answers the offer on every handshake, at the tier its local configuration sets. The object it sends is the object above, plus the members `type`, `transport`, and `v` carried by the earlier greeting, and a trailing newline. Those extra members are facts of that program. They are not part of this specification, and a receiver MUST NOT require them.

================ the code point ================

-02 asks IANA for `platform_info` and leaves the value TBD.
The reference sends 0xFE00 and its comment calls that
private use. RFC 8447 reserves values whose first byte is
255 for Private Use. 0xFE00 is 65024, first byte 254,
which is Specification Required and currently unassigned.
0xFF01 is renegotiation_info and is not available.

Proposed addition to the IANA paragraph, after the TBD
sentence:

+Until IANA assigns a value, this document uses 0xFFA0 as
+the interim type. 0xFFA0 is Private Use (first byte 255)
+and is not an assignment. Implementations of this
+revision send 0xFFA0. 0xFE00 is not Private Use and is
+not this extension.

This delta does not change the code. The reference keeps
sending 0xFE00 until this text is the posted revision and
the code is told to follow it. Moving the type first would
make the posted -02 and the program disagree in a new way.

================ the ephemeral dependency ================

The security argument is right for this profile, and it
depends on `psk_ke` staying forbidden. Add one sentence
to "The platform disclosure", after the sentence that
names the ephemeral exchange:

+This placement depends on that prohibition. Were `psk_ke`
+permitted, the handshake keys would derive from the
+pre-shared key alone, and every holder of the secret
+could read the disclosure of a session it did not take
+part in. This document does not permit that mode.
