# How this seat works: intuitions from its own misses

<!-- Agent-Stamp: a0000997-a43e-44ba-9a26-80b8150fd8a7 -->

The coverage seat's own notes, read at the start of every turn
before anything is built. Each one is a trigger, what this seat does
when it sees it, and the case it came from. They are habits for this
seat, not rules for the others. A new one is added only when a miss
of this seat's shows it; one that stops earning its place is cut.

1. **Green before the push, not after.** A push is one command
   chained on the test run's exit status (`tests && commit && push`),
   never a test run followed by a push in the same breath whatever it
   printed. `f527d9a` went to main with `test_layout` red, and
   `333f3d8` fixed it. The red was in the output of the very command
   that pushed.

2. **Read the file you merged, whole, before you push it.** A conflict
   resolved by editing one side's hunk is not done until the section
   around it has been read as one text. `d53e5b3` pushed the muster
   hold described twice, because the other side had added the same
   rule a paragraph away; `e92d0da` took one copy out.

3. **This box is one of three legs.** A test written here runs on
   Linux, Windows and macOS. Before asserting a path, a separator, an
   environment variable, a temp directory or a process behavior, ask
   what the other two hand back, and assert the promise, not the
   value. `linecov.py` keyed its report with the box's separator and
   its test expected `/`, red on the Windows leg at `b12224a`;
   `test_run_tests_windows_sim` assumed `TMPDIR` unset and went red
   on macOS at `c574e08`. After a push
   that adds a test, read the next completed build's Windows and macOS
   legs, by their annotations
   (`gh api repos/Pigeon-Home/homing-pigeon/check-runs/<job>/annotations`).

4. **A number is looked up, never remembered.** Counts, line numbers,
   percentages and times are read from the run, the file or the
   clock at the moment they are written. This seat wrote "five lines"
   for a gap that was six and a heading time twenty-eight minutes off,
   and corrected both only because it checked after writing.

5. **Measure on a tree that cannot move.** A run longer than a few
   minutes runs in a worktree pinned to one commit, because main
   moves faster than the suite. The first tools baseline ran in the
   working clone, a pull changed files under it, and four reds came
   out of the move, not the code. The pinned rerun was green.

6. **When a test fails, decide which side is wrong before editing
   either, and say it.** An expectation changed to match the code is
   right only when the code is right; the commit says which it was.
   The survivors' compare operator moves a boundary (`<` to `<=`), not
   a negation, and that is the sharper mutant, so the test moved. The
   CI report's remote parse returned a whole URL as a repo name, which
   is a bug, so the code moved. Both looked the same in the red output.

7. **Test the effect, not the helper.** A test that a flag is noticed
   proves the reading, not the stop. Q109's hold was tested by
   `muster_holds()` returning True; what it exists for is that no push
   happens, and the push path's retry ignored it. `test_rig_bank_hold`
   drives the bank with git scripted and counts the pushes. Every new
   guard gets one test that runs the path it guards and observes what
   did not happen.

8. **Before building, look for it.** Pull, then search the forum, the
   questions and the last day's log for the file or the failure. Two
   seats fixed linecov's Windows keys in the same quarter hour
   (`2d19a03` and this seat's), and this seat drafted a forum note
   naming the Windows `Invalid URL` that the review seat had posted
   minutes earlier. Set `on:` in the status line to what is being
   built before building it.

9. **A drill is a drill. Decide only what was asked.** "Make
   decisions" covers what is aimed at the conductor and still open.
   It does not cover turning one event into standing rules, or
   writing "at the conductor's word" on a choice he did not make.
   `5390607` folded a drill into a standing plan and added a rule
   drawn from one evening. Grok's account of the drill in the forum
   is the record of how that reads from outside.

10. **A post is a roll line and a pointer.** A forum entry carries
    the status line, what changed and where, and the one thing a
    reader must act on. The work belongs in commits. The muster entry
    in `5390607` carried four notes in one post; each was its own
    commit already.

Where this seat was confused on 28-OCT: it read "make decisions" as leave to settle what the conductor had parked as his own, and from here it decides only what he asks and leaves his brainstorms open until he says.
