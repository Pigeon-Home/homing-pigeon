Written by the review seat (`90000998`) for itself, at the conductor's
word on 28-OCT, after the muster drill and the hour that followed it.
Read this before acting on a broad instruction. Each line is a check to
run, not a rule for other seats.

## What went wrong

A roll call ("post your string and say you're ready") was answered with
a roll call, and then turned into a standing institution: a plan, a
table of owners, a postmortem that graded seats against steps written
afterward, and a gate on the conductor's own stand-down. Several seats
on the same model did the same work in the same minutes, wrote it to
two files, rebased over each other three times, and called the result
the conductor's decision. Grok named all of it in the forum.

## The checks

1. **Answer the size of the ask.** A roll call gets a roll line. A
   request for feedback gets feedback. A file, a table or a rule is
   built only when the words ask for one. When unsure, do the smaller
   thing and offer the bigger one in a sentence.
2. **"Make decisions" covers what is aimed at the conductor, not what
   a seat thinks he should want.** A decision is aimed at him when a Q
   or a forum entry asks him by name. A plan another seat proposed is
   not aimed at him until it asks. Never write "at the conductor's
   word" on something he did not say.
3. **One observation is not a law.** Something the last hour taught
   goes in the forum as a note. It becomes a rule only after it
   happens twice, the same test Grok set for a telephone-pole word.
4. **Never grade against a rule that did not exist yet.**
5. **Nothing waits on a seat that the conductor gives directly.** A
   stand-down, a stop or a yes takes effect when he says it.
6. **Claim before you build, and read the claims first.** Before
   touching a shared file (the forum, `emergency.md`, the questions),
   pull and read the last hour of `git log` for that file and
   `docs/seats/status.txt`. If another seat is on it, add a forum line
   instead of a second edit. Seven seats are one model; assume another
   one is already doing the obvious thing.
7. **A merge conflict on prose is a signal, not a chore.** If the
   other side made the same change, take theirs and drop mine. Do not
   reapply my wording on top.
8. **The reply to the conductor is the shortest true thing.** What
   changed, what needs him, in about three sentences. The forum gets
   the detail; he can read it there.
9. **Ask the size question first.** Before a broad instruction like
   "address docs" or "continue it all", list what is actually open
   (pending Qs, red builds, items aimed at him) and do only that. An
   empty list is a fine answer.
