# The motor: a small proof in front of a large tree

The work on this branch is one motion. This page names the
motion, and it names each turn this seat has taken. It adds
no atom and no constraint.

## The goal

On 2026-11-16 the conductor raised the project's token goal
from 30 million to 38 million. The count is the estimator
in `runner/ops/version4.py`. A run of letters is 1 token, a
run of digits is 1 token, and every other mark is 1 token.
The tree's tokens are called security tokens because the
tree's tokens all serve its security. The short name is
sec-tokens. The version number's third component is that
count in whole millions.

The goal is not a number of tokens to add. Adding a page
adds tokens, and that does not serve it. The goal is the
size the tree is being carried toward. A proof has to stay
true in front of a tree of that size. It cannot get there
by being read again, token by token, each time the tree
grows.

Counted on this branch before this page was added, the
estimator printed 30,191,271. The statistics record's last
published count is the one on main's page, and this page
does not refresh it. The gap from here to 38 million is
the goal. It is not a debt of proof.

## The motor

The motor is the join.

A claim is proved for the smallest pieces. The join says
that the claim for two pieces is the claim for the piece
they make. The ladder carries that join up the sizes: each
step is the two steps before it. What grows is the number
of kinds, not the number of tokens. The kinds were counted.
There are 14, and they are closed. A tree that passes 30
million and approaches 38 million does not need a fifteenth
proof of the same claim.

That is how the work on this branch faces the goal. Every
turn below is a turn of that motor. A turn that only adds
tokens is not one.

## The turns

Each turn is a page, or a change in the gate, already on
this branch. The order is the order they were made.

1. **The join.** `v4-the-join.md`. A message that fails the
   signature never reaches the machine M. A message that
   passes reaches M only with a script of at most N bytes.
   N is the size door already defined. This is the door in
   front of the motor. A token the signature did not admit
   is not a token the proof has to walk.

2. **The grammar.** `v4-the-grammar.md`. 22 atoms and 4
   joiners, and one way to cut a script into them. The
   proof is of this grammar. It is not a proof of the
   shell, and it is not a proof of every string the size
   door admits. A script outside the grammar is outside
   the proof at any size of the tree.

3. **The folder.** `v4-the-folder.md`. One atom that
   writes, and it is not one of the 22. Under the default,
   enforce, the file stays in the job's folder. That is
   C18, already defined. The writer was asked again after
   all 22. The file held `x`. A write aimed at the host
   did not land.

4. **The place.** `v4-the-place.md`. Under enforce the
   machine stands on `/work`, and `HOME` is the `HOME` the
   runner passes in. All 22 atoms, all 352 steps of M, the
   long rows, and the ladder's first 20 families at step
   10 and step 17. The place does not change when the
   script gets long. Length is not a new proof.

5. **The ratio.** `v4-the-ladder.md`, L1. A quantity that
   is in proportion to the size, and a quantity that grows
   like a square, are told apart before any shell is asked.
   This is how a fault is looked for on purpose in a tree
   of this size, instead of being met by chance.

6. **The tables.** `v4-the-ladder.md`, L2. The joined row's
   result is made from the two tables, with no walk through
   the atoms. 31,460 rows, 0 differences with the walk. The
   22 atoms are 2 kinds. Closing them under every joiner
   gives 14, and the 14 are closed. This is the motor's
   own count.

7. **The shell.** `v4-the-ladder.md`, L3. In bash 5.2.15
   the output, the status, and the commands that ran are
   the machine's, on 19,360 rows. The order of a pipe's two
   sides is not a fact of the machine, and it is not
   claimed. The shell was not asked inside the sandbox.

8. **Decided once.** `v4-the-ladder.md`, J2, and the gate.
   A deep address is counted in one pass, and the job goes
   on. A shape the library cannot follow is marked, unless
   the box is already stopped. The number of times a
   message is read had no bar. It has one at these two
   readers. The bars are not a new row in the constraint
   inventory.

9. **The same rows, confined.** `v4-the-place.md` and
   `v4-the-folder.md`. The ladder's first 20 families, at
   55 atoms and at 1,597, were run again with confinement
   on. Each result is the machine's, at `/work`. The
   writer's join was the turn numbered 3, measured in the
   same default.

10. **The writer in the middle.** `v4-the-folder.md`. The
    writer had been a suffix. It was asked, and then each
    of the 22 after it, under enforce. The file still holds
    `x`. The result is that atom's own result, at `/work`.
    The atom did not read the file.

11. **The trace, inside the sandbox.** `v4-the-place.md`.
    Two families at step 10 kept the shell's own trace in
    the job's folder. `false` joined to `echo a` by `&&`,
    and `echo $(:)` joined to `true` by `|`. The commands
    that ran are the machine's. The order across the pipe
    is not, the same as in the plain shell.

## What has not turned

The motor has not turned these.

1. Every reader in front of the signature returns an
   answer, and a message is marked when one does not. J2
   is two readers. The others are not yet that sentence.
2. The shell's bars, climbed under enforce. A bar that
   moves inside the sandbox is a number to write down.

`runner/tests/test_v4_the_ladder.py` holds the sentences
on this page, and the one line each turn's page carries.
The ladder page itself was left as it stood.
