# Stage 8 — P1 at 50,000 characters

This is the record of the gate property family checked at a
script bound of 50,000 characters: P1(50000), the nine
clauses of `properties.md` for every handling whose script
has at most 50,000 characters. The stage was defined and
not run. This is its own run.

`stage6-cap.md` recorded this rung as the same searched
set as the re-run at the production cap. That argument
stands, and this stage does not replace it. What this
stage adds is the run itself at the 50,000 bound, so the
rung's claim rests on a check run at its own bound.

## How the bound was set for this run

The bound is a declared interpretation in `Gate.tla`'s
header, not a state variable. The copy of the model on
`main` keeps the production-cap declaration, which
subsumes this rung. For this check, a scratch copy was
taken whose header declares P1(50000), and whose
`GateEnforce.cfg` comment names it. The scratch copy was
diffed against the tree copy before the run. The
difference is that header and that one configuration
comment, and nothing else. No action, invariant, or
message field differs. `Claim.tla` is unchanged.

TLC 2.19, each run exhaustive, on Java 17. Every run
starts from 786,432 initial states, and the depth of each
gate search is 18, as at the earlier rungs.

rung changes is the set of real handlings the graph
stands for. `P1Inv` holding over that set is, at this
rung, P1(50000).

## The two counterexamples that are supposed to exist

`GateWitness.cfg` (`NothingExecutes`, audience enforce)
fails with a counterexample ending at `outcome = "execute"`
for a message that satisfies every clause — 3,095,425
generated, 2,308,999 distinct. A good job still executes.

`GateDefaultWitness.cfg` (`AudienceWasRequired`, audience
off) fails with a counterexample ending at
`outcome = "execute"` with `audienceOk = FALSE` —
3,106,561 generated, 2,320,141 distinct. Clause 4 is
still vacuous when the audience feature is off, and still
checked for real under enforce.

## The conformance family after the check

`runner/tests/test_proof_constraints.py`,
`runner/tests/test_proof_conformance.py`, and the
companions `test_proof_conformance_p2.py` through
`test_proof_conformance_p6.py` run 253 tests, all
passing. `runner/tests/test_skip_registry.py` runs 5
tests, all passing. The check changed no runner
behaviour and no model file on `main`.

## What this does not say

P1(50000) holding says nothing new about the rungs above
it. The model's scope is otherwise the first rung's
scope, and the cryptography is assumed, not proven. The
content-independence series is a different artefact, and
this rung does not add to it.
