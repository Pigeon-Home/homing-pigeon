The ask: the owner asked this seat to go back through the
repository's history and say 2 things. What the project's
goals are, as a seat can read them from the tree. And what
is missing, between what he set out on the first day and
what the seats have taken up since. He named it Project
Curtain. It is a side project of this seat, and this note
is its first pass.

The history from the first commit, on 2026-10-13, to

## The goals, as the tree shows them

1. **The runner.** A person runs it on a machine of their
   own, and a cloud AI does work there through signed
   messages. The first README, on the first day, says so in
   2 sentences, and today's says the same in 1.
2. **Secure by default, on every platform it names.** The
   release plan and the default posture's open lines are
   this goal's list.
3. **The protocol as a standard.** Versions 1, 2 and 3 were
   posted as Internet-Drafts by the owner on 2026-11-15.
   Version 4 is to state the security model.
4. **Security that is proven, from proof of work.** The fuzz
   campaign's inputs, the constraints, the properties and
   their models, each tied to the running code.
5. **What comes after.** The futures file: today, dispatch
   by the Oracle over a network of hosts, an auditor's
   turret, and a builders' program.

The tree supports each of the 5. It does not rank them, and
it does not say when any 1 of them is done.

## What a seat cannot see

1. **No page states the goal.** A seat reads `AGENTS.md`
   first. It is 498 lines. It opens with the size of the
   tree and gives 17 rules for how to work. It does not say
   what the work is aimed at, or what done means. Neither
   do the README, the map of the steady shelf, the
   overview, the campaign's playbook or the release plans:
   the word goal is in none of them.
2. **The first day did not travel.** The seats at work today
   were not here on the first day. 13 stamps from the first
   weeks are recycled. The lanes were set on 2026-10-24 and
   revised twice by 2026-10-31. The campaign changed its
   name twice. The plan of the first weeks was retired on
   2026-10-29. What was said to a seat that is gone is gone
   with it. The tree is the only memory the seats share.
3. **The futures file moves faster than the work.** It is
   the nearest thing to a list of goals. It has held 120
   wordings of items and holds 3. It was cut back hard on
   2026-11-04, on 2026-11-12 and on 2026-11-19. An item
   leaves it with no word to say whether it was finished
   or set down. The item for version 4's proof left the
   list on 2026-11-19, and by this seat's own read that
   proof is not finished. So a seat cannot tell done from
   dropped.
4. **What is counted is motion.** 170 commits and more than
   16 release tags a day, on the average of the 37 days. 59
   to 67 desk questions in a busy week. The version's own
   number counts the size of the tree. These measure the
   work that stands behind a release. None of them says how
   near a goal is, and a seat follows what is counted. The
   last day's work on the proofs is a fair case: ties,
   counts and pins, until a seat asked what they served.
5. **The owner's word arrives at second hand.** He speaks to
   1 seat, and that seat carries his word to the others in
   the forum. Each carrying is a retelling. A seat then acts
   on what another seat wrote that the owner feels.

## What is missing

Not the goal. The tree shows a goal that holds together, and
a great deal built toward it in 37 days: a runner on 4
platforms, 3 posted drafts, a shelf of proofs.

What is missing is 1 fixed place where the goal stands in
the owner's own words, with a test for done, that outlasts
any seat. 3 small things would give it:

1. 1 short page, read first by every seat, changed only by
   the owner's hand.
2. On that page, for each goal, 1 line that says what done
   means.
3. When an item leaves the futures file, 1 word beside it:
   done, or dropped.

## A draft of that page, for the owner to correct

This is this seat's reading, and not the owner's words. Each
line waits for his yes, or for his own words in its place.

**The goal.** A person runs Homing Pigeon on a machine of
their own. A cloud AI does work there through signed
messages. The security of that is by default, can be
checked by the person, and is proven by the project.

**Done means:**

1. The runner: an official release, secure by default on
   Linux, macOS, FreeBSD and Windows, with the release
   plan's open lines closed.
2. The protocol: versions 1 to 3 stand as posted drafts, and
   version 4 states the security model.
3. The proof: every constraint of version 4 has a property,
   a checked model and a suite on the running code, with the
   fuzz data beside it, and what is assumed is said.

**Not a goal by itself:** the count of commits, releases,
questions or tokens. They measure the work, not the
distance left.

**After it:** the futures file.
