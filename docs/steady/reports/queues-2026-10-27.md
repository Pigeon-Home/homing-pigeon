# Queues, seen working (2026-10-27)

A one-tenant Cloudflare Worker and one Linux runner, version
3.14.2, exchanged a real ping. Nothing below is a secret. The
Worker's hostname, the runner token, the SI token and the HMAC
secret are not in this file.

## What was standing

The Worker is the one-tenant shape: `TENANT`, `SI_TOKEN`,
`RUNNER_TOKEN` and `HMAC_SECRET`, the last three stored as
secrets. The Durable Object binding is `TENANT_QUEUE`. The
runner was installed with the `hosted` profile and
`transports: ["queues"]`. Its queue URL is the Worker's
`/t/homingpigeon02` base. The runner token is the blob's
`transport_queues.token`, because the system unit does not set
an environment variable and `token_env` would have been empty.
Poll interval 20 seconds. The runner dials out. Nothing on it
listens.

## What a stranger sees

| Request | Result |
|---|---|
| `GET /t/homingpigeon02/jobs` with no bearer | `401 {"error":"runner token"}` |
| `GET /t/not-a-tenant/jobs` with no bearer | `404 {"error":"unknown tenant"}` |

The first line means the tenant is configured and the call was
refused for want of the runner token. The second means any
other slug is not this deployment.

## The ping

At 21:03:36 UTC the SI posted one ping. The Worker accepted it
with `202`. The id was `67afed13-2d34-4065-8f9e-8571b433d7c3`.

The runner, which had been pulling since 21:00:56 UTC, logged
this on the next poll:

```text
transport queues: extension queues v1.0.0 by Homing Pigeon started
transport queues: queues transport: pulling from <worker>/t/homingpigeon02
seq transport: job 67afed13-2d34-4065-8f9e-8571b433d7c3 submitted by transport
executing job 67afed13-2d34-4065-8f9e-8571b433d7c3 (kind=ping)
job 67afed13-2d34-4065-8f9e-8571b433d7c3 done (exit=0)
result 67afed13-2d34-4065-8f9e-8571b433d7c3 delivered (attempt 1)
```

Startup beside that: `judge=advisory`, `ceiling=attested`,
`workspace=/data/work`, `workers=1`.

The SI then read `GET /results?max=3` with its bearer and got
`200` and one result. The envelope is the encrypted form
(`hp_enc`), and it names key `k-7e1ec001`, which is the
fingerprint of the shared secret and not the secret. The body
was not decrypted for this note.

At 21:38 UTC the same runner was still active and still
pulling. No second job had been posted.
