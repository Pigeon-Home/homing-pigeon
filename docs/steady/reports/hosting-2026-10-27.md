Measured on a box with no package index, so with
`runner/tools/linecov.py` (the standard library's `sys.monitoring`,
Python 3.13) instead of coverage.py. Lines only, no branches. The
data beside this file is the tool's report, in coverage.py's JSON
shape, and `runner/tools/coverage_gaps.py` reads it unchanged.

## What was measured

| Report | Sources | Tests |

| `send-job-2026-10-27.json` | `runner/cloud/send_job.py` | every module that names `send_job` (2,003 tests; the two `test_platinum_*` modules need `hypothesis` and did not load) |

## What is still not run, and why

- `runner/hosting/cli.py`, 7 lines: the script-mode import fallback
  (5 lines; the suite imports the package), `sys.exit(main())` under
  `__main__`, and the closing `return 2` after the subcommand switch,
  which argparse makes unreachable.
- `runner/hosting/fly.py`, 1 line: the `return False` after
  `raise_for`, which always raises there.
- `runner/transport_extensions/queues/__main__.py`, 2 lines: the
  `__main__` exit and one `continue` in the pull loop that only a
  second item with the same id reaches.
- `runner/cloud/send_job.py`, 46 lines, outside the queue code: the
  largest are in `write_outputs` and `cmd_keyring`'s error paths.
  They belong to the inline-files and key-name work and are listed in
  the JSON for whoever takes them.

## Regression pass on the same tree

`runner/tools/run_tests_parallel.py`, two shards: 7,174 tests. The
failures were the ones this box always shows (the `hypothesis`
modules that do not load here, `ConftestSeedHookTests`, and
`test_gamma`, the parallel runner's own fixture), plus three that
passed on a rerun alone: `test_query_pattern_bound`'s slow-match kill
and `test_regression_guard`'s end-to-end case, both timing under the
two-shard load, and `test_skip_registry`, which ran while
`test_linecov`'s two skip reasons were being registered.
